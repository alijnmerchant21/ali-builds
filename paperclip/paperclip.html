01 · Why it stalls

Race the hello probe

Before an agent can run, Paperclip sends a "Respond with hello" probe through OpenCode. That probe carries the full agent prompt. On a cloud model it comes back in seconds. On a laptop, the model has to read about 16,000 tokens first. Miss the deadline and the agent sits in "Verifying" forever, so every task just says "queued". Flip the settings below and see what happens.

A rough model, not a benchmark. Numbers come from my Ollama logs: 15,928 prompt tokens, prompt speeds between 285 and 590 tok/s on an M1 Max with qwen3:8b.

02 · The recipe

From zero to a local agent in 6 steps

Tested on a MacBook Pro M1 Max with 32 GB, Ollama 0.40, OpenCode and the current Paperclip release. Linux works the same minus the arch prefix in step 1.

1

Start Ollama on the GPU, with room to think

On Apple Silicon, check that your Terminal isn't running under Rosetta (uname -m should say arm64). If it does, Ollama quietly runs on the CPU. The bigger context window and keep-alive matter as much as the GPU.

OLLAMA_FLASH_ATTENTION=1 OLLAMA_KV_CACHE_TYPE=q8_0 \
OLLAMA_CONTEXT_LENGTH=32768 OLLAMA_KEEP_ALIVE=-1 \
arch -arm64 ollama serve
2

Pull a model and install OpenCode

Paperclip runs local models through the OpenCode harness. Use 14B if you have the memory. Section 03 explains why.

ollama pull qwen3:14b
npm install -g opencode-ai
3

Add the Local endpoint connection

The first onboarding screen leads with cloud subscriptions. The Local endpoint lives one level deeper. New agent, harness OpenCode, then Connection, then Connect an account, then expand Advanced providers, then Local endpoint. Base URL:

http://localhost:11434/v1

Pick "Enter custom model" and use paperclip/qwen3:14b. Under Advanced, set Runner to Legacy runner.

4

Give the hello probe more time

This is the step that unblocks everything. The setting exists in the OpenCode adapter but not in the UI, so set it through the local API. Replace the agent name with yours.

CID=$(curl -s http://127.0.0.1:3100/api/companies | python3 -c "import sys,json;d=json.load(sys.stdin);d=d.get('companies',d) if isinstance(d,dict) else d;print(d[0]['id'])")
AID=$(curl -s "http://127.0.0.1:3100/api/agents/local-agent?companyId=$CID" | python3 -c "import sys,json;print(json.load(sys.stdin)['id'])")
curl -s -X PATCH "http://127.0.0.1:3100/api/agents/$AID" \
  -H "Content-Type: application/json" \
  -d '{"adapterConfig":{"helloProbeTimeoutSec":300}}'

Don't hit Save on the agent form afterward. It doesn't know about this field yet.

5

Teach the agent how to close a task

Paperclip's built-in skill is 809 lines. A local model loses the one line that matters. Paste this into the agent's Instructions. Keep the curl on one line. When I split it across lines, the model dropped the backslashes and the shell failed.

## Closing a task (local model rules)
When the work is done, use your bash tool to run exactly this. Do not use webfetch. Do not invent URLs.

curl -s -X PATCH "$PAPERCLIP_API_URL/api/issues/$PAPERCLIP_TASK_ID" -H "Authorization: Bearer $PAPERCLIP_API_KEY" -H "Content-Type: application/json" -d '{"status":"done","comment":"done"}'

Check the reply contains "status":"done". If it does not, say the update failed.
Write files only in the current working directory.
6

Resume, run the test, assign a task

New agents start paused, and the paused banner can stay up after you resume. Trust the header buttons instead. Click Run test on the Harness page, wait for "Connection successful", then assign work. Expect minutes, not seconds.

04 · Troubleshooting

The things that cost me an afternoon

Ollama log says library=cpu and total_vram 0 B

Your shell is running under Rosetta, so the universal Ollama binary picked its Intel half. Start it with arch -arm64 ollama serve, or untick "Open using Rosetta" in Terminal's Get Info.

"Agent verification failed: the execution test timed out"

The hello probe hit its 60 second limit while the model was still reading the prompt. Do step 4. Keeping the model loaded and turning on flash attention help, but aren't enough by themselves on a laptop.

The model list only shows cloud models

The list follows the Connection. Switch the Connection to your Local endpoint, then choose "Enter custom model".

Tasks stay "queued" or "Waiting to start"

Either the agent is still verifying (see above) or it was never resumed. Clicking Run now repeatedly just stacks more queued runs, so cancel the extras.

Runs never get faster, even with the model loaded

Ollama's prompt cache only matched the first ~5,900 tokens between runs, so ~10,000 tokens get reread every time. The OpenCode adapter puts a random temp folder path into the system prompt on every run. Open PR #17209 already fixes this. Until it lands, every local run pays the full reading cost.

Ollama's default context is 4k

Paperclip's prompt is ~16k, so a 4k window silently truncates it. Set OLLAMA_CONTEXT_LENGTH=32768.

05 · What I'd fix upstream

What's already in flight, and what isn't

I checked the tracker before writing this. Two of these fixes already have open PRs from the community. Two don't exist yet.

Not reported yet

Raise the probe timeout for local endpoints

helloProbeTimeoutSec defaults to 60s for OpenCode and isn't in the agent form. Show it in the UI, or default it to a few minutes when the Connection is a Local endpoint.

Open PR #17209

Keep the prompt prefix stable

Already diagnosed and fixed in #17209. My Ollama logs back it up: the cache matched only the first ~5,900 of ~16,000 tokens.

Open PR #15884

Put local on the first screen

#15884 adds a Local LLM tile to onboarding. That would answer most of the "stuck on onboarding" reports in #14104.

Not reported yet

A short skill for small models

A compact version of the Paperclip skill covering the few API calls every agent needs, so local models stop guessing URLs or faking a finished task.
